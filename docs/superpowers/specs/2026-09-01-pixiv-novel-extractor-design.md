# Pixiv 小说提取油猴脚本设计

## 目标

创建一个单文件油猴脚本，在 Pixiv 小说详情页识别并提取小说标题与正文。脚本同时支持当前单篇和所属系列，结果既可复制到剪贴板，也可下载为 UTF-8 编码的 `.txt` 文件。

## 范围

- 运行页面：`https://www.pixiv.net/novel/show.php?id=*`。
- 提取对象：当前账号在浏览器中原本有权访问的小说。
- 支持当前单篇及当前小说所属的整个系列。
- 将 Pixiv 正文标记转换为适合阅读的纯文本。
- 所有处理均在浏览器本地完成，不上传或收集内容。

不包含 EPUB、Markdown 等额外格式，不绕过登录、年龄分级、作者可见性或区域限制，也不提供站外批量抓取入口。

## 技术方案

采用“结构化数据优先、页面 DOM 兜底”的混合提取方式。

1. 从当前 URL 解析小说 ID。
2. 优先使用当前登录会话请求 Pixiv 页面使用的结构化作品数据，读取标题、正文及系列信息。
3. 若结构化数据不可用，则从当前已经渲染的页面中提取单篇标题和正文。
4. 系列模式先获取有序的作品 ID 列表，再按顺序逐篇请求并合并结果。

结构化数据适合准确提取正文和系列顺序；DOM 兜底可在部分页面数据机制变化时继续支持当前单篇。若系列列表接口不可用，系列操作会给出明确错误，不从页面猜测不完整的章节列表。

## 用户界面

脚本在小说详情页添加一个不遮挡正文的“提取小说”浮动按钮，并注册同等功能的油猴菜单命令。点击按钮后展示四项操作：

- 复制当前小说
- 下载当前小说
- 复制整个系列
- 下载整个系列

当作品不属于系列时，系列操作禁用并说明原因。系列提取期间显示“已处理章节数 / 总章节数”；操作完成或失败时显示简短状态，不使用阻塞式弹窗反复打断用户。

## 文本格式

单篇文本格式：

```text
作品标题

正文
```

系列文本以系列标题开头，各作品之间使用明显的章节分隔：

```text
系列标题

===== 第 1 篇：作品标题 =====

正文
```

正文转换规则：

- 注音转为 `汉字（读音）`。
- 章节标记转为独立标题行。
- 分页标记转为空行分隔。
- 跳转标记转为可读的页内跳转提示。
- 插图标记保留为带作品 ID 的文本提示，不下载图片。
- 统一换行为 `\n`，压缩标记转换造成的多余空行，但保留作者原有段落结构。

下载文件使用 UTF-8 编码。文件名会移除 Windows 不允许的字符，并限制过长标题；单篇使用作品标题，系列使用系列标题。

## 错误处理与访问节制

- 登录失效、作品删除或无权访问时，显示可理解的错误信息。
- 系列中单篇失败时记录占位说明并继续后续作品，最终报告成功数和失败数。
- 系列请求按顺序执行，并在相邻请求间加入短暂间隔，避免瞬时并发访问。
- 复制 API 不可用时给出提示，用户仍可使用下载功能。
- DOM 兜底只用于当前已渲染的单篇，不将页面局部内容误当作完整系列。

## 代码结构

保持单文件交付，但按职责划分小函数：

- 页面识别与 ID 解析
- Pixiv 数据请求和响应校验
- DOM 单篇兜底提取
- Pixiv 标记到纯文本的转换
- 单篇与系列文本组装
- 剪贴板复制和文本下载
- 浮动面板、菜单及状态显示

各模块通过普通数据对象传递 `{ id, title, text, series }`，避免 UI、网络请求和文本转换相互耦合。

## 验收标准

1. 在可访问的 Pixiv 单篇小说页能准确提取标题及完整正文。
2. 四项操作中，适用于当前作品的操作均可正常完成。
3. 系列结果严格按照系列章节顺序合并，并展示处理进度。
4. 注音、章节、分页、跳转和插图标记按照设计转为可读纯文本。
5. 单篇失败时提供明确原因；系列中的个别失败不阻止其他章节导出。
6. 生成的 `.txt` 可在常见 Windows 文本编辑器中以正确字符和换行打开。
7. 脚本不向 Pixiv 以外的服务发送小说内容或用户数据。

## 验证策略

- 对 URL/ID 解析、文件名清理和正文标记转换进行本地函数测试。
- 使用模拟的单篇、系列、无权限和部分章节失败响应验证数据流。
- 在实际 Pixiv 单篇及系列详情页手动验证按钮、菜单、复制、下载和进度状态。
- 模拟结构化数据失败，确认当前单篇可使用 DOM 兜底，系列则明确报告不可用。

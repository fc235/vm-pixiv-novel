# Pixiv 插画与漫画原图下载设计

## 目标

在现有 Pixiv 小说提取油猴脚本中增加插画与漫画作品下载能力。用户打开任意 `https://www.pixiv.net/artworks/{id}` 作品页后，可通过右下角面板下载当前作品：单图直接保存原图，多图将所有可成功取得的原图打包为 ZIP。

功能只处理当前浏览器账号原本有权访问的当前作品，不遍历推荐内容、作者其他作品或站外资源，也不绕过登录、年龄分级、可见性及区域限制。

## 页面与功能范围

脚本支持两类页面：

- 小说详情页 `https://www.pixiv.net/novel/show.php?id=*`：保留现有小说复制、单篇下载及系列下载功能。
- 插画/漫画作品页 `https://www.pixiv.net/artworks/*`：显示“下载当前作品”操作，支持单图和多图作品。

“当前作品的全部图片”指 Pixiv 为该作品返回的全部分页原图，不包含评论、推荐区域、关联作品、缩略图或当前浏览器尚未展示的其他作品。

## 数据获取

1. 从作品页 URL 解析数字作品 ID。
2. 使用当前 Pixiv 登录会话请求作品信息，取得标题和分页数量。
3. 请求当前作品的分页数据，按 Pixiv 原有顺序取得每页 `original` 原图 URL。
4. 原图请求通过 `GM_xmlhttpRequest` 以二进制方式完成，允许访问 `i.pximg.net`，并保留 Pixiv 页面作为来源信息。
5. 若作品数据缺失、响应结构异常或没有原图 URL，显示明确错误，不从页面缩略图猜测原图地址。

数据接口封装、图片二进制请求、下载策略和 UI 控制器保持分离，并通过依赖注入接受请求、ZIP 和文件下载实现，以便自动化测试。

## 单图下载

单图作品不创建 ZIP：

- 请求唯一原图，失败后自动重试一次。
- 成功后使用浏览器本地 Blob URL 和油猴下载 API 保存原始格式文件。
- 文件名使用 `[pixiv_作品ID] 清理后的作品标题.扩展`，扩展名从原图 URL 读取并限制为常见图片扩展；无法识别时使用 `.jpg`。
- 下载完成或前不提前释放 Blob URL；成功或失败后均释放该 URL。
- 两次请求均失败时不生成文件，面板显示失败原因。

## 多图 ZIP 下载

多图作品按分页顺序逐张请求，每张失败时自动重试一次。成功图片使用保留原扩展名的零填充页码命名，例如 `001.jpg`、`002.png`。页码宽度至少为三位，超过 999 页时按总页数扩展宽度。

失败处理以作品总页数为分母：

- 每次重试仍失败后，计算 `失败页数 / 总页数`。
- 比例不超过 20% 时继续处理，最终生成包含成功图片的 ZIP，并加入 UTF-8 文本文件 `下载失败.txt`，逐行记录失败页码、原图 URL 和简短错误原因。
- 比例一旦超过 20% 时立即停止剩余请求，不生成 ZIP，并显示“已失败页数 / 总页数”。
- 失败比例正好为 20% 时按“不超过 20%”处理，允许生成部分 ZIP。

ZIP 文件名使用 `[pixiv_作品ID] 清理后的作品标题.zip`。JPEG、PNG、GIF 等图片本身通常已经压缩，因此 JSZip 使用 `STORE` 模式，避免无意义的重复压缩和额外 CPU 消耗。ZIP 只在浏览器内存中生成，不上传到任何服务。

## 用户界面

插画/漫画页面复用现有 Shadow DOM 浮动面板的视觉样式和持久化最小化行为：

- 面板标题显示“Pixiv 作品下载”。
- 提供一个“下载当前作品”按钮，同时注册同名油猴菜单命令。
- 加载作品信息时显示准备状态。
- 图片请求期间显示 `正在下载原图：已处理 / 总数`。
- 生成 ZIP 时显示“正在生成 ZIP”及 JSZip 提供的百分比进度。
- 完成时明确显示单图已下载，或 ZIP 成功图片数和失败图片数。
- 下载期间禁用操作按钮，避免用户重复启动同一任务；完成或失败后恢复。
- 最小化状态与小说页共用现有布尔偏好，因此在两类页面间跳转时保持用户选择。

小说页面的标题、三个操作按钮、剪贴板修复、系列下载及状态行为保持不变。

## 依赖、权限与版本

脚本继续以单个 `.user.js` 文件交付，并增加：

- `@match https://www.pixiv.net/artworks/*`
- `@grant GM_xmlhttpRequest`
- `@connect i.pximg.net`
- 固定版本 `JSZip 3.10.1` 的 `@require` 地址

外部依赖必须使用包含明确版本号的 HTTPS URL，不使用浮动的 `latest` 地址。脚本版本从 `0.2.0` 提升为 `0.3.0`，名称和说明调整为同时覆盖小说提取及作品下载。

## 错误与资源管理

- Pixiv API 请求失败、权限不足、响应结构变化和下载失败均转换为用户可理解的状态消息。
- 每张原图最多请求两次，不无限重试。
- 图片按顺序请求，避免瞬时并发访问；相邻请求不额外加入长时间等待。
- 多图在内存中持有成功图片直至 ZIP 生成完毕。README 明确提示：页数多或原图很大的作品可能占用较多内存。
- 用户关闭页面或浏览器中止请求时，不承诺断点续传。
- 所有创建的 Blob URL 在油猴下载成功或失败回调后释放。
- 文件名沿用并扩展现有 Windows 非法字符清理逻辑。

## 代码边界

保持现有单文件结构，但新增或扩展以下小型职责单元：

- 页面路由解析：区分小说 ID 与作品 ID。
- Pixiv 作品客户端：映射作品信息及分页原图列表。
- 二进制请求适配器：将 `GM_xmlhttpRequest` 封装为 Promise。
- 图片命名与失败比例计算：纯函数，可独立测试。
- 作品下载器：实施重试、阈值、单图直下和多图 ZIP 策略。
- 作品控制器：管理忙碌状态、进度和用户消息。
- 页面启动器：根据路由创建小说或作品面板及菜单。

不拆分新的运行时脚本文件，不实现设置页面、下载队列、作者批量下载、跨作品下载、断点续传或自制 ZIP 格式。

## 自动化验证

Node 测试至少覆盖：

1. 仅接受合法的 Pixiv 作品 URL 和数字作品 ID。
2. 作品信息及分页原图 URL 映射保持 Pixiv 顺序。
3. 单图成功时下载原始格式文件而不调用 JSZip。
4. 图片首次失败、第二次成功时继续完成。
5. 多图全部成功时按零填充页码写入 ZIP。
6. 失败比例正好为 20% 时生成部分 ZIP并包含 `下载失败.txt`。
7. 失败比例超过 20% 时停止剩余请求且不生成 ZIP。
8. 单图两次失败时不生成文件。
9. Blob URL 在成功和失败回调后均释放。
10. 作品页面板、菜单、忙碌状态和进度消息正确。
11. 现有小说复制、小说下载、系列下载和最小化测试继续通过。
12. 用户脚本语法检查通过，元数据包含固定 JSZip 版本及最小权限。

## 手工验收

在已登录 Pixiv 的 Tampermonkey 环境中分别验证：

- 单图 JPEG 或 PNG 作品直接下载原图，文件可正常打开。
- 多图且无失败的作品生成按页码排序的 ZIP。
- 模拟少量失败时 ZIP 包含成功图片及 `下载失败.txt`。
- 模拟超过 20% 失败时不生成 ZIP。
- 大于 9 页的作品文件顺序正确，进度持续更新。
- 小说页原有三个功能及最小化状态没有回归。

## 验收标准

1. 所有插画和漫画作品页均出现“下载当前作品”，单图直下原图，多图生成 ZIP。
2. 多图每页最多重试一次，并严格按 20% 阈值选择部分 ZIP 或中止。
3. ZIP 内图片顺序、扩展名和失败清单准确，文件名可在 Windows 使用。
4. 操作期间有进度且不能重复启动，完成或失败后恢复可用。
5. 登录与作品访问限制得到遵守，内容不离开浏览器本地处理。
6. 现有小说功能、剪贴板行为和持久化最小化功能保持不变。
7. 自动测试、语法检查及 Tampermonkey 手工验收均通过。
